# 架构与威胁模型

[English](ARCHITECTURE.md)

## 组件

可执行文件包含两个相互独立的运行模式：

1. `collect` 在备份宿主机上短时运行。它读取配置指定的标记、受长度限制的日志文件、systemd 属性、进程匹配结果、可选的 ZFS 状态及显式依赖探针，然后原子替换一个经过脱敏的 JSON 文档。
2. `serve` 是长期运行的非特权 HTTP 进程。它在每次 API 请求时读取该文档，并提供构建时嵌入的前端资源。

这种隔离是有意设计的。即使 Web 进程被攻破，攻击者也不应获得 Restic 密码、异地存储服务商令牌、仓库写权限、宿主机进程参数或 Docker/systemd 控制 socket。

## 数据最小化

公开状态契约只允许显示名称和运行数据：

- 时间戳、持续时间、字节总量、百分比和短快照 ID；
- 配置的任务名称和依赖项名称；
- 白名单事件标题及三个数字型详情字段；
- 规范化的服务状态和退出状态；
- 聚合健康判断。

原始命令输出和任意日志消息绝不会复制到状态 JSON。非时间戳的代次 ID 会转换为单向的 12 位十六进制指纹；快照 ID 只保留最多 12 个安全字符；事件详情只接受整数型的 `duration_seconds`、`snapshots` 和 `rc`。标记和日志读取器会拒绝符号链接。

## 信任假设

- 采集器配置属于等同代码的可信输入，因为命令依赖和进程匹配使用显式参数数组或子字符串规则。配置应归 root 所有，且备份任务和 Web 用户均不可写。
- 备份任务可以写入标记、JSON 摘要和事件文件。采集器会限制文件大小，严格解析时间戳和数值，并只投影安全字段。
- 脱敏状态目录不得包含秘密信息。向 Web 容器只挂载该目录。
- 身份认证和 TLS 有意交由成熟的反向代理处理。内置服务默认监听回环地址，不承担身份提供方职责。

## 失败行为

- 任务定时器缺失或失败、服务结果失败、依赖项不健康以及存储检查失败，都会转化为可见的健康状态。
- 缺少成功的恢复审计时，系统绝不会给出“可恢复”结果。
- 当文档缺失、无效、过大、过旧或生成时间不合理地超前时，`/readyz` 返回 `503`。
- `/healthz` 只报告进程是否存活，让编排系统可以区分进程存活与采集数据过期。
- 采集写入使用同目录临时文件、`fsync`、`0644` 权限和原子重命名，Web 服务不会读到写入一半的文档。

## 网络暴露面

HTTP 服务只接受 `GET` 和 `HEAD`。它会设置 CSP、防嵌套、`nosniff`、Referrer、Permissions Policy 和 Cross-Origin-Opener 等响应头。API 响应使用 `no-store`，静态资源最多缓存一小时。

项目提供的容器会丢弃全部 capabilities，以 UID/GID 65532 运行，使用只读根文件系统，并以只读方式挂载状态数据。

## 维护者变更规则

应将 `status.json` 视为带版本号的公开 API 契约。修改状态时，必须同步更新模型、采集器、服务端校验、前端、演示数据、测试以及中英文文档。不兼容变更需要明确决定是否提升结构版本，不能悄悄改变现有字段的语义。

新增观测数据应投影为有界、强类型、白名单化的值。不要公开任意命令输出、路径、进程参数、日志消息或凭据。需要备份写权限、仓库凭据、身份认证或调度能力的功能不应进入只读 Web 进程，并且必须经过明确的威胁模型评审。
